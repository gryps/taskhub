## 当前续接点

Phase 0–6 核心源代码能力已完成。Phase 7 已移除活动应用中的物理主机和远程节点路由、
后台监控与协调任务，只保留历史数据/模块作为升级回滚兼容边界；生产就绪检查已改为 Seed
本机 Docker 节点管理。仓库质量 CI、真实 Git/PostgreSQL 交付与重启恢复验收、项目预检中心
也已建立。统一异常处置中心已完成：它从检查点和任务索引投影等待、阻塞与失败任务，提供分类、
严重度、原因和既有恢复动作，并通过 PostgreSQL、重启恢复和真实浏览器验收。统一证据中心、
模型运营面板和跨平台只读备份验证也已完成。当前续接点是 Phase 7 全量回归、发布安全检查与
交付文档收口。

Phase 6 将项目并发、优先权重和运行成本冻结进计划，
提供加权公平调度、20 个全局并发槽位、千任务 Ready 聚合、关键路径/宽度/成本/批次预测、
集中瓶颈与证据质量分析，以及每页 100 项的执行计划文本视图。

项目预检 API 统一检查仓库、模型、本机执行、契约、质量命令和验收依赖，并控制新任务入口。
生产就绪 API 逐项检查持久化编排、HTTPS 会话、RBAC、审计、备份身份、Socket Proxy 和
本机节点管理。复杂生产画布继续由 `taskhub-web` 独立维护，其余三个控制台路由在具备完整能力
等价前保留原生实现，不复制可编辑调度状态。真实目标环境发布/恢复演练留在部署门禁；本轮
只提交 Git，不部署或构建镜像。

Phase 7 当前本地回归、React 测试/构建、真实 Git/PostgreSQL 发布恢复验收均已通过；项目
预检、异常处置、证据中心与模型运营真实浏览器验收覆盖桌面/手机宽度。正式目标环境部署、
镜像构建与发布仍需单独发布授权。

源代码门禁已完成。目标环境部署、Docker 镜像构建与镜像仓库发布仍作为独立发布动作，必须在
确认版本号、回滚点和目标仓库后执行。
