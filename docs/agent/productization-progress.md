## 当前续接点

下一阶段严格从 Phase 5 开始。Phase 4 已建立持久化 ChangeRequest 生命周期和可解释影响分析：
显式任务、变化路径、未完成任务及其所有下游组成受影响子图，验证任务自动形成回归范围。
应用已批准变更时生成同一计划的下一版本；受影响任务使用替代 ID 和全新 attempt，未受影响且
已验证的任务复制只读结果与证据引用，原计划、原任务和原 attempt 保持可追溯。

调度批次包含计划版本，控制器重启不会与旧版本冲突。自动修订受项目上限约束，超过上限后
转为人工批准；开发流程卡片可提出变更、查看重跑/复用/回归范围并批准、应用或拒绝。
权限、CSRF、同源认证与既有交付执行权限一致，1440、680、390 像素下均采用统一卡片字阶且
无页面级横向溢出。Phase 4 验证结果为完整 Python 套件 `254 passed, 16 skipped`、
TypeScript/Vite 生产构建成功，以及真实 Google Chrome 三档视口全部通过。

开发发布约束：每阶段完成后只提交并推送 `.3 Git` 与 GitHub；暂不部署、不构建 Docker
镜像、不上传镜像仓库。
