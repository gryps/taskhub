# TaskHub V2 产品化交付 Phase 6 实施说明

状态：源代码实现完成

更新日期：2026-09-12

## 交付范围

Phase 6 将前五阶段的单项目生产模型扩展为可持续运行的多项目控制面：

- 项目可配置 1–20 个并发任务、1–10 优先级权重和单次运行成本预算；策略在
  `ExecutionPlan` 创建时冻结，后续修改不改变历史计划。
- 全局调度支持至少 20 个同时 Running 的任务。跨项目采用累计授权量/权重选择，既让高
  权重项目获得更多机会，也保证低权重项目持续前进。
- Ready 重算先计算本地依赖、治理和锁条件，再按任务类型与能力集合合并远程能力检查；
  1,000 个同类任务只触发一次等价能力探测。
- 任务成本按 small/medium/large 映射为 1/3/8 单位。调度器在派发前核对计划预算，超过
  预算的任务保留明确等待原因，不产生无证据的执行尝试。
- 执行计划 API 返回全图分析和分页任务。分析包含关键路径、最大并行宽度、剩余成本与
  批次预测、预算余额、失败/复用/证据完整率及集中资源锁或等待原因。
- 开发流程增加统一 14/13/12px 的“运行策略”卡片和“执行预测与瓶颈”卡片；任务文本视图
  每页 100 项，提供明确范围与上一页/下一页，不一次渲染无限任务。
- `/api/system/production-readiness` 对正式持久化编排、HTTPS/Secure Cookie、持久会话与
  密钥轮换、四角色 RBAC、管理审计、备份密钥身份、Docker Socket Proxy 和节点协调逐项
  给出可机读判断与修复提示。

## 正式运维验证边界

权限、审计、备份恢复和升级的源代码合同由自动化测试持续验证：管理 API 服务端授权、
CSRF、登录限流、会话撤销、安全响应头、受限 Docker Socket Proxy、升级失败自动回滚、
备份校验和以及加密主密钥—数据库身份匹配。真实生产发布/恢复演练必须使用目标环境的
数据、卷和镜像执行；本阶段遵循“只推送 Git、不部署、不构建镜像”的发布约束，因此不把
外部演练伪记为已执行。

## 前端迁移结论

生产画布继续由独立 `taskhub-web` 承担复杂拓扑交互。任务中心、开发流程和系统配置暂时
保留原生页面，因为它们尚未达到完整路由迁移所需的等价能力；服务端 API 是两类前端的
唯一状态来源。Phase 6 不在 React 与原生前端各维护一套可编辑 DAG、Ready 或调度逻辑，
后续只按完整路由迁移并在等价验收后删除旧路由。

## 验收依据

- 1,000 任务 Ready 分组重算与关键路径分析分别低于 2 秒；
- 500/1,000 任务图由相同非递归 O(V+E) 分析路径处理；
- 全局预算测试达到 20 个同时占用槽位且不越限；
- 多项目加权公平测试证明高优先级生效且低优先级不饥饿；
- 执行计划文本视图具有服务端分页，常规运行更新继续通过既有 SSE 推送；
- 完整 Python、React 构建、静态前端和响应式浏览器结果记录在阶段提交说明中。

阶段验证结果：完整 Python 套件 `271 passed, 19 skipped`；React/TypeScript/Vite 生产构建
通过；真实 Google Chrome 在 1440、680、390px 下通过策略卡、分析卡、任务卡列数与页面级
横向溢出检查；JavaScript 语法、changed-file Ruff、架构约束和 `git diff --check` 通过。

## 回滚

Phase 6 只增加项目策略默认字段、分析响应和只读诊断接口，不修改既有生产对象表。旧项目
自动获得默认策略；关闭 `TASKHUB_PRODUCTION_ORCHESTRATION_ENABLED` 继续回到旧线性运行。
回滚代码不会删除任何 ProductSpec、ProjectContract、ExecutionPlan、Task 或 Attempt 历史。
