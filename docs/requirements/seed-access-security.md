# TaskHub Seed HTTPS、访问安全与权限需求

状态：首个产品化闭环已实现（2026-09-11）

## 目标

Seed 必须在不暴露宿主机完整 Docker API、浏览器会话密钥或用户密码的前提下，支持多用户协作和可追溯的管理操作。安全默认值属于正式 `deploy/release` 交付契约；源码开发模式可以显式关闭 HTTPS，但不得绕过认证、权限或 CSRF。

## 访问安全

- 正式安装默认生成一张 397 天的初始自签名证书并以 HTTPS 启动；生产环境应替换为企业 CA 或公开 CA 证书。
- HTTPS 部署强制 `Secure`、`HttpOnly`、`SameSite=Strict` 会话 Cookie；CSRF Cookie 采用双提交校验。
- 所有认证后的非只读 API 都必须通过 CSRF；登录与首次设置依靠不可预测密码/初始化口令，并受同源 Cookie 策略保护。
- 默认会话空闲 30 分钟、绝对有效期 12 小时；主动注销写入服务端撤销状态，不能重放旧 Cookie。
- 同一来源与用户名 15 分钟内连续失败 5 次，锁定 15 分钟。服务返回统一失败信息，不枚举用户。
- 响应必须设置 CSP、禁止 iframe、MIME 嗅探、外部 Referrer 和浏览器高风险能力。
- 会话签名密钥可在 Web 轮换；轮换保留上一把密钥用于安全迁移，但立即撤销全部既有会话。
- 配置加密主密钥仍属于离线启动根配置。它与 PostgreSQL 备份身份绑定，必须通过备份—重加密—恢复流程轮换，不能在 Web 中显示或直接替换。

## 角色与权限

| 角色 | 权限边界 |
| --- | --- |
| 管理员 | 用户、密钥、主机、凭据、节点、模型、平台、项目、任务和发布 |
| 项目负责人 | 项目管理、任务执行、审批和发布；只能读取平台资源 |
| 开发人员 | 读取项目与资源、创建和处理交付任务；不能管理项目注册、发布或基础设施 |
| 只读审计人员 | 只读查看任务、证据、资源与审计；任何写操作均拒绝 |

内置 `admin` 不能删除。其他用户存入持久化数据卷，密码使用独立随机盐的 scrypt 哈希；API 和审计绝不返回哈希。主机与 SSH 凭据、模型凭据、节点凭据只允许管理员管理。

## 管理审计

登录成功、失败、限流、注销、拒绝访问及所有认证后的管理写操作必须记录时间、操作者、角色、方法、API 路径、结果与状态码。日志使用既有脱敏器，不能记录密码、Cookie、CSRF、令牌、私钥或请求正文。

## Docker Socket 隔离

正式 Compose 使用 `ghcr.io/tecnativa/docker-socket-proxy:v0.5.0`。只有 Proxy 容器挂载宿主机 Socket；控制器仅访问内部 `http://docker-proxy:2375`。Proxy 允许 TaskHub 所需的容器、镜像、网络、卷、信息、版本与 ping API，显式禁止 Swarm、Secret、Service、Plugin、Build、Auth、Exec、Pause 等接口，且不发布宿主机端口。

这显著缩小控制器的暴露面，但 Proxy 自身因持有 Socket（并按上游要求使用 privileged 模式）仍等同宿主机高权限，创建容器也仍是高权限操作。因此只有管理员可触发容器管理，TaskHub 仍需校验镜像、网络、卷和启动参数，Proxy 网络不得暴露到外部。

## 验收标准

- HTTPS 健康检查通过，Cookie 含 `Secure`、`HttpOnly`、`SameSite=Strict`。
- 超时、注销和签名密钥轮换后，旧会话返回 401。
- 失败阈值到达后正确返回 429；成功登录会清除该身份的失败计数。
- 四种角色分别通过正向和越权测试；拒绝操作返回 403 并进入审计。
- 直接查看控制器 Compose 不存在 Docker Socket 挂载；Proxy 不发布端口且禁用非必要 API。
- 用户界面在 1440、680 和 390 像素下无页面级横向溢出，非管理员不显示用户编辑表单。
