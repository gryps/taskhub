# TaskHub Seed 日志、主机维护与备份恢复需求

## 目标

Seed 应在不依赖维护人员登录远程主机的情况下，完成工作节点诊断、物理主机维护和自身灾难恢复。所有能力复用现有主机、远程节点、独立凭据和期望状态，不建立平行库存。

## 日志与诊断

- 工作节点诊断聚合 Agent 事件、容器最近日志、SSH/Docker 操作轨迹、节点最后错误、CPU/内存/磁盘及槽位占用。
- 日志读取限制条数和响应大小，不返回节点令牌、私钥、API 密钥或仓库密码。
- 一键诊断包采用 ZIP，包含系统、主机、节点、容器和操作记录的 JSON 快照；地址与敏感字段强制脱敏。
- 诊断包不得包含业务备份、数据库转储、环境文件、模型账号令牌或加密主密钥。

## 主机维护

- 主机状态为启用、排空、维护、停用或指纹阻断。非启用状态不接收新任务。
- 排空从调度库存移除节点，但不强制中断已经取得槽位的任务。
- 定期检查 SSH 指纹、Docker、回连网络、CPU 负载、内存和磁盘；指纹变化必须阻断，不允许自动接受。
- 资源不足产生明确告警。停用主机跳过周期连接，重新启用前必须重新检测。
- 批量重建保留源主机数据卷。跨主机操作只重建容器和期望状态，不暗示数据卷已迁移。

## Seed 备份恢复

- 正式备份包含 PostgreSQL 全量转储、TaskHub 数据卷、部署 `.env`、Compose 文件和回退镜像。
- 数据卷覆盖管理员密码哈希、模型账号文件、节点独立凭据、项目与运行数据；数据库覆盖模型/平台配置、SSH 加密凭据、主机和节点库存。
- 数据库持久保存配置加密主密钥的单向身份指纹。启动、备份和恢复都必须验证身份匹配。
- 恢复前校验所有文件 SHA-256、备份环境中的主密钥指纹及数据库身份表；恢复后再次查询身份，匹配后才启动控制器。
- 业务备份包含敏感材料，不通过 Web 下载，并应保存到访问受控的加密介质。

## 验收

- 未认证用户不能访问诊断、维护或备份信息。
- 指纹变化、资源不足、主机排空和停用会使节点退出新任务调度。
- 诊断包可解压、字段完整且敏感值与 IP 地址已脱敏。
- 使用错误主密钥的恢复在破坏现有数据卷之前失败。
- Linux 与 Windows 发布脚本均通过语法、备份和隔离恢复演练。
