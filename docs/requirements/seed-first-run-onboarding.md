# TaskHub Seed 首次启动向导需求

状态：快速开发 Alpha 已实现

版本：0.1

更新日期：2026-09-11

## 1. 目标

用户启动 `taskhub-seed` 后，不需要进入多个页面自行判断配置顺序。首次设置管理员
密码并登录后，系统自动进入初始化向导，持续回答三个问题：还缺什么、下一步去哪里、
何时能够运行任务。

## 2. 初始化步骤

向导按以下顺序展示并实时检测：

1. 管理员密码已设置；
2. Seed Docker Engine 可访问，并能读取 Docker 可用 CPU、内存和 TaskHub 持久化磁盘；
3. Seed 对外地址和 Node Agent 回连地址已经保存且生效；
4. 默认工作节点镜像已存在于 Seed，或已配置镜像仓库/国内代理；
5. 所选模型服务配置已经生效；
6. 至少一个 Seed 本机工作节点健康且已加入调度。

全部条件满足时，向导和系统运行概览必须显示“系统已具备运行任务条件”。条件不满足
时不得只显示红色状态，必须给出下一步入口。

## 3. 交互要求

- 未完成初始化时，管理员登录后自动进入向导；用户可以选择本次会话稍后处理。
- 向导不复制模型、平台和节点表单，而是复用系统配置中的唯一配置入口。
- 每个步骤显示明确的已完成/待完成状态、诊断摘要和“去完成”动作。
- 系统配置页长期保留“首次启动向导”入口，初始化完成后仍可重新检查。
- 模型或平台配置等待重启时，向导提供 Seed 容器快速重启操作，并等待健康恢复。
- 向导状态由服务端实时计算，不依赖浏览器 localStorage 作为完成依据。

## 4. Seed 主机资源口径

CPU、内存、操作系统和架构来自 Seed 所连接 Docker Engine 的 `/info`，在 Docker
Desktop 上代表分配给 Linux Docker VM 的任务容量，不等于 Windows 物理机总资源。
磁盘显示 TaskHub 持久化数据所在文件系统的可用容量，保证这个数值与实际可写空间相关。

本 Alpha 只要求资源指标可读取，不设置统一的最小 CPU、内存和磁盘门槛。后续应根据
节点角色和并发槽位建立容量建议与阻塞阈值。

## 5. 离线镜像导入

- Web 接收由 `docker save` 生成的 tar 包和期望镜像引用；
- 上传文件最大 20 GB，暂存文件在导入结束或失败后立即删除；
- 通过 Docker Socket 调用 Docker Engine 导入镜像；
- 导入后必须按期望引用重新读取镜像 ID、摘要、操作系统和 CPU 架构；
- 返回上传包 SHA-256，不把镜像包保存到 Git、数据库或 TaskHub 数据卷；
- 镜像必须先在打包端带有与平台默认镜像一致的 tag。

## 6. 就绪判定边界

本版本固定采用单 Seed 模式，不存在远程物理主机就绪条件。健康工作节点必须由 Seed
本机 Docker 创建并注册，前端和服务端使用相同的六步就绪判断。

模型与平台配置如果仍处于等待重启状态，不能计为已经生效。镜像条件允许“Seed 本地
已有镜像”或“远程仓库/代理已配置”二选一；在线初始化会预拉取 Node 镜像，节点健康仍
由本机创建节点流程进行最终验证。

## 7. Alpha 限制

- 未实现镜像上传进度百分比和断点续传；
- Web 重启依赖 Seed 容器使用 `unless-stopped` 或等效自动重启策略；
- 尚未按角色计算最低资源容量；
- 首次向导复用系统配置表单，配置完成后需要返回向导重新检测。
