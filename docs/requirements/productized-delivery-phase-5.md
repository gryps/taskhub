# TaskHub V2 Phase 5：能力包框架与前端设计合同

状态：已完成

日期：2026-09-12

## 目标

把前端风格、组件、布局、品牌、响应式和无障碍要求从临时提示词提升为受信、版本化、
可兼容校验且可追溯的项目事实。所有前端任务只能使用 ProductSpec 锁定的精确能力包版本，
并消费由控制器编译的 ProjectDesignContract。

## 已交付能力

1. CapabilityPack 清单覆盖唯一编号、语义化版本、类型、来源、摘要、兼容矩阵、文件、资产、
   模板、规则、验证器、许可证、资产授权、可执行声明、权限、内容和稳定清单摘要。
2. 平台启动时安装 7 个受信内置包，组成现代企业控制台、轻量产品门户和数据密集工作台
   三套前端推荐。每套同时包含风格、原生组件、布局和中性品牌四类精确版本。
3. 管理员可以导入清单草稿、审查并信任、停用和重新启用。路径穿越、绝对路径、凭据、
   超过 1 MB 的清单、无许可证、无资产授权以及未声明权限的可执行内容会被拒绝；导入内容
   保存在生产对象中，不展开到控制器文件系统，也不会作为任意脚本执行入口。
4. 推荐器根据 TaskHub 规格版本、项目档案、语言、框架和互斥声明过滤，最多返回三套兼容
   组合以及登录、列表、详情和移动端代表性预览。
5. 项目选择生成 CapabilityPackLock 草稿。锁文件只接受语义化精确版本，不允许 `latest`；
   激活前再次核对包信任状态、最新草稿和当前 ProjectContract 兼容性。
6. 激活后编译 ProjectDesignContract，冻结设计令牌、组件、布局、品牌、响应式、无障碍、
   视口和验证证据。ProductSpec 记录同一组精确版本，ExecutionPlan 和每个任务记录锁及设计
   合同版本，工作节点收到编译后的项目合同而不是重复解释通用包。
7. 前端项目没有与当前 ProductSpec 版本完全匹配的活动锁时，规格批准或 DAG 编译会被阻止。
   ProductSpec 修订即使沿用同一包版本，也必须生成与新规格版本绑定的新锁和设计合同。
8. 更换能力组合先生成新锁草稿及迁移任务，旧锁和旧设计合同保持活动；只有明确激活后才
   废弃旧版本。已批准规格必须先创建规格修订，不能在原版本上静默升级设计包。

## API 边界

- `/api/capability-packs`：读取平台库存；
- `/api/capability-packs/import`：管理员导入清单草稿；
- `/api/capability-packs/{id}/versions/{version}/trust`：审查并信任；
- `/api/capability-packs/{id}/versions/{version}/availability`：停用或重新启用；
- `/api/projects/{project_id}/capability-recommendations`：读取最多三个兼容方案；
- `/api/projects/{project_id}/capability-lock`：读取活动锁、待激活草稿和设计合同；
- `/api/projects/{project_id}/capability-locks`：生成项目锁草稿；
- `/api/projects/{project_id}/capability-locks/{version}/activate`：明确激活并编译合同。

库存读取遵循项目查看权限；导入、信任和全局可用性由平台管理员控制；项目锁选择和激活由
管理员或项目负责人控制。所有写入继续受会话、CSRF 和服务端 RBAC 保护。

## 界面与验收

- 开发流程新增“设计与能力包”同级折叠栏目；一张当前合同卡同时呈现活动锁、待激活升级
  和迁移任务，三张推荐卡展示用途、四类精确版本以及四种代表性预览。
- 系统配置的“平台设置”下新增能力包库存二级卡片，负责导入、信任和可用性管理。
- 1440px 为三列推荐，681–1100px 为两列，680px 及以下为单列；所有状态均同时使用文字
  和颜色，核心字阶保持 14/13/12px。
- 自动化验证覆盖兼容推荐、安全导入、信任、锁定、升级、过期草稿、停用包、规格修订、
  DAG 绑定、工作节点上下文和真实浏览器三档视口。
