# TaskHub V2 Phase 2：项目契约与结构门禁

状态：已完成

日期：2026-09-12

## 目标

把项目结构、依赖方向、质量命令、迁移策略和交付物约定从提示词提升为版本化、可审批、
可执行的 ProjectContract。实现任务只有在绑定已批准 ProductSpec 和已生效
ProjectContract 后才能启动。

## 已交付能力

1. 提供 `fullstack-web`、`backend-api`、`frontend-spa`、`python-service`、
   `worker-service` 五类官方项目模板，定义目录、模块、依赖方向、质量命令、容器健康、
   文档和仓库策略。
2. 新项目按所选模板自动生成契约草稿；接入已有仓库时扫描语言和框架，形成待项目负责人
   核对的推断草稿。
3. ProjectContract 使用统一生产对象仓储持久化，支持草稿、评审、生效、废弃、拒绝和严格
   连续修订版本；已生效版本内容不可原地修改。
4. 每个版本生成精确的 `.taskhub/project.yaml`、`.taskhub/architecture.yaml` 和
   `.taskhub/acceptance.yaml`，并将契约快照与三份文档注入规划和实施上下文。
5. 自动门禁覆盖目录、模块依赖方向、循环、文件及函数复杂度、跨层数据库访问、API 源与
   生成客户端摘要、迁移顺序与回滚、敏感凭据、二进制及许可证、Docker/Compose 健康约定、
   项目质量命令和声明交付物。自然语言规则必须提供人工证据。
6. 门禁报告包含结构化 finding，并作为 `architecture_compliance` 验收证据；失败会返回实施
   修订，不能进入发布。
7. 开发流程增加项目契约卡片，统一呈现模板、版本、状态、技术栈、模块、命令、机器文档、
   审批信息和门禁结果；项目创建类型统一为五类正式模板。

## 兼容与安全边界

- `TASKHUB_PRODUCTION_ORCHESTRATION_ENABLED=false` 时不强制契约，旧流程保持可运行。
- TaskHub 不直接修改已接入项目；契约只通过不可变上下文交给执行节点，代码变更仍由受控
  工作区和发布流程完成。
- 门禁命令使用项目配置的测试调度器执行，不获得控制面凭据。
- 当前阶段不包含真实任务 DAG；该能力进入 Phase 3。

## 验收结论

- 故意构造的反向跨层依赖、依赖循环、重复迁移序号、缺失回滚、敏感凭据、无许可证二进制
  和缺失声明交付物均会导致门禁失败。
- 运行会记录 ProjectContract 编号和版本；无生效契约时，即使 ProductSpec 已批准也不能
  开始实施。
- 项目契约卡在 1440px、680px 和 390px 下保持统一字阶、正确列数且无页面横向溢出。
