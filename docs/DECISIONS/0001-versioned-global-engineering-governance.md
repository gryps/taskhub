# ADR-0001：版本化全局工程治理

## 背景

全局 `AGENTS.md` 能约束本机 Codex 会话，但 TaskHub 执行节点、历史计划和批次验收无法仅凭该文件获得稳定、可审计的规则快照。直接在每次提示中读取最新文件还会使运行中的计划发生隐式漂移。

## 决定

1. 使用独立 `EngineeringPolicy` 作为全局规则唯一事实来源。
2. `ProjectContract` 保存 `PolicyBinding`，冻结规则 ID、版本、内容摘要、适用规则和执行指令。
3. `ExecutionPlan`、`ProductionTask` 和编码上下文继承该绑定，不在后续阶段重新解析最新规则。
4. 自动检查进入合同门禁；无法可靠自动化的要求使用人工证据门禁。
5. 临时偏离规则使用有期限、需审批的 `PolicyException`，不直接修改或关闭门禁。
6. 规则升级只影响新合同或明确建立的合同修订。

## 备选方案

- 每次从 Seed 文件系统读取 `AGENTS.md`：无法保证容器可见性和历史可复现性，否决。
- 把全部规则复制到每个项目：产生多份事实来源，否决。
- 只在最终验收检查：不能阻止批次级架构漂移，否决。

## 代价

- 项目合同新增规则迁移步骤。
- 人工证据规则需要项目负责人提供可审查记录。
- 批次集成后增加一次静态门禁，但质量命令仍复用任务级执行，避免重复运行完整测试。
