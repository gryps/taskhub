# TaskHub 操作手册

适用地址：`http://192.168.31.31:8123`

本手册只说明已经接入的“抖店管理平台”如何发起和跟踪一次开发需求。

## 一、登录和检查

| 步骤 | 点击位置 | 填写/操作 | 正常结果 |
|---|---|---|---|
| 1 | 浏览器打开控制中心 | 使用现有管理员账号登录 | 进入“总览” |
| 2 | 左侧“系统设置” | 不填写，查看系统状态 | 控制中心、PostgreSQL、Redis 显示正常 |
| 3 | “系统设置”中的节点区域 | 点击刷新节点 | 显示 4 个 Worker；实施、质量和 Windows GUI 节点可见 |
| 4 | 左侧“模型调度” | 查看角色和 Provider 状态 | 角色有可用模型；失败项会显示代理、额度或认证原因 |

系统检查未通过时不要创建开发工作流，先处理红色或失败状态。

## 二、同步项目代码

| 步骤 | 点击位置 | 填写/操作 | 正常结果 |
|---|---|---|---|
| 1 | 左侧“项目治理” | 顶部项目选择“抖店管理平台” | 页面加载该项目的治理信息 |

## 三、创建完整开发需求

### 点击位置

`项目治理` → `开始首个完整需求`

### 填写内容

1. “要完成的需求”：填写业务目标、开发范围、禁止事项和验收要求。
2. “选择生产线”：普通单项需求选择 `电商开发 A 线`。
3. 点击“创建完整工作流”。

推荐输入格式：

```text
业务目标：
说明这次要解决什么问题。

开发范围：
1. 需要修改的功能。
2. 允许修改的模块或目录。

禁止事项：
1. 不操作生产数据库。
2. 不部署生产。
3. 不修改范围外项目。

验收要求：
1. 用户可以观察到的结果。
2. 必须通过的测试。
3. 必须提交的报告或制品。
```

### 正常输出

页面下方显示：

- `workflow`：本次工作流 ID。
- `created`：已创建任务数量。
- `next`：下一步操作提示。

随后工作流进入“规划中”或“待计划审批”。

## 四、批准开发计划

### 点击位置

`任务中心` → `任务跟踪` → 选择类型为 `review.human` 的待处理任务。

### 检查内容

- “需求”是否与原始输入一致。
- “审批后任务”是否覆盖实施和测试。
- 修改目录是否属于抖店管理平台。
- 是否错误包含生产发布、真实凭据或其他业务项目。
- 五角色证据链是否已经生成。

### 操作

1. 通常不要直接修改 `approval_plan` JSON。
2. 在“审批原因”填写，例如：

```text
范围和验收标准正确，同意进入开发；禁止部署生产。
```

3. 点击“批准并创建下游任务”。

### 正常输出

- 当前人工审批任务变为 `succeeded`。
- “已创建下游”出现实施、检查或测试任务。
- 工作流进入“实施中”。

发现计划错误时点击“阻塞”；确定不再执行时点击“取消”。

## 五、查看开发进度

### 点击位置

`任务中心` → `五角色工作流` 或 `任务跟踪`

### 状态含义

| 状态 | 含义 | 用户操作 |
|---|---|---|
| `pending` | 等待依赖或 Worker | 正常等待 |
| `running` | Worker 正在执行 | 查看任务详情和心跳 |
| `succeeded` | 当前任务完成 | 等待下游任务 |
| `failed` | 执行失败 | 查看错误后决定是否重试 |
| `blocked` | 条件不足或人工阻塞 | 解决原因后恢复处理 |
| `canceled` | 已取消 | 不再继续 |

点击某个任务后，右侧“任务详情”应显示：

- 目标 Worker。
- 所属流水线。
- 输入和执行结果。
- 重试次数。
- 上游和下游任务。
- 错误码或输出摘要。

不要仅因为耗时较长就重复创建同一需求。

## 六、查看各角色结果

| 菜单 | 查看内容 | 正常结果 |
|---|---|---|
| 规划编排 | 需求拆解、任务顺序、模型输出 | 计划清晰且没有越界 |
| 开发实施 | 代码任务、变更计划、diff | 修改发生在独立工作区和分支 |
| 审查验收 | 审查结论、API/Web/Executor 测试 | 显示通过，或列出明确失败项 |
| 风险报告 | 残余风险、上下文和阻断项 | 风险有等级和处理建议 |
| 监督裁决 | 汇总证据和监督模型建议 | 显示批准、返工或阻塞建议 |

角色自动执行已经启用。正常情况下只需要等待流程推进，不要手工重复触发同一个角色。

## 七、最终批准或返工

### 点击位置

`监督裁决` → 选择状态为“待监督裁决”的工作流。

### 检查内容

- 实施结果和修改文件。
- 测试是否实际运行并通过。
- 审查是否有未关闭问题。
- 风险模型是否报告高风险。
- 监督模型给出的最终建议。
- 代码是否已经推送到正确分支。

### 操作和输出

| 点击 | 结果 |
|---|---|
| “批准完成” | 工作流进入“已完成” |
| “要求返工” | 工作流返回“实施中”，返工次数增加 |
| “恢复处理” | 已阻塞工作流重新进入可执行阶段 |
| “取消” | 工作流终止 |

“批准完成”只结束 TaskHub 工作流，不代表批准生产部署。

## 八、查看输出文件

### 点击位置

`项目治理` → `制品交换中心`

### 正常输出

可以看到 Worker 上传的：

- 测试报告。
- H5 截图。
- 日志摘要。
- 代码或检查结果文件。
- 文件大小和 SHA-256。

点击对应制品下载。找不到制品时，先回到“任务中心”确认任务是否成功以及 Worker 是否上传文件。

## 九、失败处理

| 现象 | 点击位置 | 处理 |
|---|---|---|
| 模型调用失败 | 模型调度 | 检查 Provider、代理、登录和额度 |
| 任务长时间 pending | 任务中心 | 检查父任务、流水线状态和目标 Worker |
| Worker 离线 | 项目治理 → 节点与设备 | 点击“检测设备”并查看节点状态 |
| 任务 failed | 任务中心 → 任务详情 | 阅读错误，确认原因消失后重试 |
| 工作流 blocked | 监督裁决 | 处理阻断原因后点击“恢复处理” |
| 修改范围错误 | 任务中心或监督裁决 | 阻塞或取消，不要批准 |

## 十、生产操作边界

TaskHub 不会因为工作流“已完成”就自动执行以下操作：

- 合并权威分支。
- 部署生产环境。
- 修改生产数据库。
- 修改账号或凭据。
- 点击抖店发布商品。

这些动作必须建立单独任务并取得人工明确批准。
