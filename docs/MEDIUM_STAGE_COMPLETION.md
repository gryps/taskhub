# 中级阶段六项收尾验收

## 1. 告警升级

- 未确认告警按持续时间升级为 L1/L2，升级通知使用独立指纹。
- 原告警确认后，尚未发送的升级通知同时被抑制。
- 升级时间可在系统设置调整。

## 2. 自动恢复

- 默认关闭且处于 `dry_run`，演练建议和执行结果均持久化。
- 白名单动作：回收过期租约、重试显式加入的失败任务、重试显式加入的角色调用。
- 动作具有冷却期、重试上限、事务锁和任务历史记录。

## 3. 模型恢复回切

- Plus/Pro/API 的首选顺序保持不变。
- 失败后指数退避；冷却结束后只允许一个恢复探针。
- 当前探针成功即可服务当前请求，连续成功达到阈值后才稳定回切。

## 4. 五角色交接协议

- 每个新任务生成 `taskhub.handoff/v1` 契约记录。
- 产物、校验结果和 payload hash 持久化，并进入审查/风险模型上下文。

## 5. 双流水线验证

- 就绪检查要求两个独立 implementation worker 均在线并声明 `code.change`。
- 200/1000 任务模拟验证 A/B 流水线无跨线领取。
- 单节点失联模拟验证对应流水线停止，另一条流水线不越权接管。

## 6. Windows 图形自动化

- `.34` 仅纳管通用的 `h5.inspect` 图形验收能力。
- 业务采集、商品处理和上架程序与 TaskHub 隔离，不注册为节点能力，也不能被 TaskHub 调度。
