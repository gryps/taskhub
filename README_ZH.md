# TaskHub V2

[English](README.md) | [中文](README_ZH.md)

TaskHub V2 是一个以 LangGraph 为原生工作流引擎的 AI 软件交付控制平面。工作流状态、自动推进、恢复执行和失败修订由图状态控制，而不是由应用自行维护一套 SQL 状态机。

当前版本：`0.1.0-alpha`

## 核心能力

- 每次开发运行对应一条可持久化、可恢复的工作流线程。
- 覆盖需求接收、规划、实现、评审、风险分析、监督和验收子图。
- 规划完成后自动进入实施，监督通过后自动发布；只有失败、证据缺失或修订超限才等待人工处置。
- 开发环境支持内存检查点，正式部署支持 PostgreSQL 持久化检查点。
- 支持 ChatGPT Plus/Pro 设备授权，以及 GPT、DeepSeek、MiniMax API 适配器。
- 支持按角色配置主模型与有序备用模型，记录冷却、额度和服务恢复状态。
- 管理 Git 权威仓库、控制器工作副本和每次任务的隔离 worktree。
- 自动执行真实代码修改、测试、补丁、提交和发布，并提供可恢复冲突处理。
- 支持带上限的监督者—开发者修订循环，并持久保存每轮证据。
- 支持认证工作节点、能力感知调度、节点槽位、任务粘性和故障切换。
- 提供 HTTP API、SSE 更新、检查点历史、任务中心和工作流时间线。

## 产品化交付

TaskHub 将需求逐步冻结为可审计的软件交付对象：

```text
原始需求
  → ProductSpec 产品规格
  → ProjectContract 项目契约
  → ExecutionPlan 执行计划与任务 DAG
  → 隔离实现和验证
  → ChangeRequest 持续修订
  → 自动监督与发布
```

- 产品规格必须经过决策、评审和批准，已批准版本不可变。
- 项目契约声明架构边界、技术栈、质量命令、迁移规则和验收要求。
- 服务端生成执行计划、动态批次、依赖、资源锁、成本与瓶颈分析。
- 每次尝试都有幂等键、独立 Git worktree、节点分配和完整证据。
- 变更请求只重跑受影响子图；复用成果会明确引用原始尝试，不伪装成新执行。
- 能力包固定前端样式、组件、布局、品牌、响应式和无障碍合同版本。

## 生产画布

`/canvas/` 提供独立的 React 生产拓扑画布，用于维护长期交付拓扑和查看最新运行叠加层。

- 支持节点拖拽、类型化连线、平移缩放、小地图、自动布局和撤销/重做。
- 草稿必须先保存并通过服务端校验，才能激活为调度约束。
- 工具栏、键盘和列表视图提供与右键菜单等价的操作入口。
- 窄屏保留节点编辑、资源绑定和校验能力，不依赖桌面拖线操作。
- 浏览器只呈现服务端结果，不自行推导 DAG、Ready 状态或节点资格。

## Seed 与工作节点

正式部署由 Seed 控制器、统一 Node 镜像和 PostgreSQL 组成。工作节点可按执行、测试或预生产角色启用能力，并由 Seed 统一管理：

- 单 Seed Docker 节点创建、生命周期和运行诊断。
- 节点创建、升级、健康检查、凭据轮换、故障回滚和重启恢复。
- 并发槽位、能力匹配、优先级、项目预算和节点故障切换。
- 测试数据库、浏览器验收、预生产部署和项目专属验收合同。
- 备份恢复、审计、会话安全和最小化 Docker Socket Proxy 权限。

## 创建或接入项目

Web 控制台的主要入口是“创建项目”。首次使用时，管理员先在“系统配置 → 高级设置 → 可管理平台参数 → Git 仓库服务”填写 SSH 用户与主机、端口、权威仓库根目录、Seed 工作副本根目录以及可选私钥，并可在保存前测试连接。TaskHub 随后可以创建 Git 权威裸仓库、初始化控制器工作副本和首个提交，也可以从同一服务发现或手工填写远端仓库并接入。

每个托管项目记录权威远端和基准分支。发布前会拉取最新权威状态，在需要时变基并重新测试；监督通过后自动执行带租约保护的推送。推送冲突会成为可恢复阻塞，绝不会被报告为成功。

TaskHub 维护者只能修改 TaskHub 本身、部署、节点、配置、诊断和测试。任何托管项目代码修改都必须由有记录的 TaskHub 开发运行产生，维护者不能绕过平台直接替项目改代码。

## 本地运行

要求 Python 3.12–3.14：

```bash
cp .env.example .env
python3 -m venv .venv
.venv/bin/python -m pip install -e '.[dev]'
make run
```

打开 `http://localhost:8200`。

## Docker Seed 控制器

Windows Docker Desktop 可运行：

```powershell
.\deploy\seed\start-seed.ps1
```

正式发布使用 `deploy/release/` 下的标准 Compose、初始化、升级和恢复流程。详细说明见：

## 架构规则

- 工作流状态转换只放在 `src/taskhub_v2/workflows/`。
- API 处理器调用应用服务，不直接修改工作流状态。
- 模型服务商和工作节点实现协议，图中不写厂商或主机专用逻辑。
- 项目专属命令和路径不进入平台核心。
- Python 模块必须少于 400 行，CI 会执行此限制。
- 所有副作用必须幂等，因为被中断的节点会从节点起点重新执行。
- 密钥只从受控运行环境加载，不通过 API、日志或诊断包回显。
